# Query language

Decides which query syntax RhizoDB accepts and in what order features arrive.

## Background

GQL is the reference language, but the only public conformance suite is the openCypher TCK, and its setup queries use Cypher syntax. The accepted syntax decides how much of that suite can run unchanged.

## Decisions

- Where GQL and Cypher differ, the GQL form is canonical.
- Cypher's `CREATE` is accepted as an extension with the meaning of GQL `INSERT`, so TCK setup queries run unchanged.
- Keywords are case-insensitive, and identifiers are case-sensitive.
- Any keyword works as a label, relationship type, property key, map key, or procedure name, and every keyword except the clause and operator words works as a variable, alias, or `YIELD` name, in any letter case.
- A variable, alias, or `YIELD` name that is a clause or operator word such as `MATCH`, `WHERE`, `AS`, or `AND` is a syntax error where the query reads it back, and a quoted name works there.
- `SET` and `REMOVE` read `NULL`, `NOT`, and `LABELED` after `IS` as operators, not labels, so a label with one of those names takes a quoted name there.
- The first features are `MATCH`, `OPTIONAL MATCH`, `WHERE`, `RETURN`, `WITH`, `ORDER BY`, `SKIP` or `OFFSET`, `LIMIT`, `INSERT`, and the core expressions over the stored value types.
- Further features are ordered by how many TCK scenarios they unlock.
- A pattern used as a predicate is accepted only inside a `WHERE`.
- `EXISTS { query }` runs the query from the current row with the outer variables in scope, and is true when the query gives a row.
- A query inside `EXISTS` may end without `RETURN`.
- A query inside `EXISTS` cannot update the graph.
- A query inside `EXISTS` keeps the variables it binds to itself.
- A variable that a projection hides from the expressions next to it is hidden inside both forms of `EXISTS` there.
- A type error that the query text alone determines fails the query before it reads data, wherever it appears in the query.
- An error that depends on values, such as overflow, division by zero, or the type of stored data, fails only when a row reaches it.
- The check on the query text reads a value error as null and goes on.
- A value read as null this way stands for any value of the type its expression gives, so the check reports a type error only when the failing step raises it whatever those values are.
- The check tracks, for each value, which parts it read as null: the whole value, or single items of a list and entries of a map.
- An operator, indexing, slicing, property access, and `size`, `keys`, `head`, `last`, `tail`, `reverse`, and `properties` take their type errors from the types of their operands alone, so only an operand read as null as a whole hides a type error there.
- Any other function hides a type error when any part of an argument was read as null.
- List and map literals, indexing, slicing, property access on a map, `head`, `last`, `tail`, `reverse`, `properties`, `coalesce` for the argument it returns, a `CASE` for the branch it takes, a comprehension for each item it projects, and the variable of a comprehension or quantifier keep track of the items and entries they pass on.
- `size` and `keys` read only how many items or which keys a list or map has, so an item read as null does not reach their result.
- `IS NULL` reads only whether its operand is null.
- Any other step that reads an item or entry read as null, such as `=`, `IN`, `+`, or a function not named above, gives a value read as null as a whole.
- `coalesce` gives a value read as null as a whole when an argument it passes over was read as null.
- A `CASE` whose choice of branch reads a part read as null gives a value read as null as a whole and evaluates no branch.
- A comprehension whose filter reads a part read as null for an item skips that item and gives a value read as null as a whole.
- A quantifier whose predicate reads a part read as null for an item gives a value read as null as a whole.
- The type error the check reports is the first one it proves, which may be a later one than evaluation would raise first if each value error had given a value.
- A type error the check skips this way still fails when a row reaches it.
- A procedure is a Rust function the host registers on a `Database` under a qualified name.
- `CALL` runs a registered procedure.
- A host procedure sees only its arguments, never the graph.
- The engine provides built-in procedures in the reserved `db` namespace, and they read the graph of the transaction that calls them.
- A host cannot register a procedure in the `db` namespace.
- No procedure writes the graph.
- `CALL` is a reading clause.
- Procedure names are case-sensitive.
- Each procedure parameter declares the types it accepts.
- Procedure arguments fall under the same checks as function arguments.
- Every procedure parameter accepts null.
- An integer argument to a float parameter arrives as a float.
- A query that is a single `CALL` returns the `YIELD` items, or every output without `YIELD` or with `YIELD *`.
- A query that is a single `CALL` may leave out the arguments, which are then read from the query parameters of the same names.
- `COUNT { ... }` takes the same bodies as `EXISTS` under the same scope rules, and gives how many rows its query gives or how many times its patterns match.
- `COLLECT { query }` gives, as a list in row order, the one column that its query's final `RETURN` gives, and any other query is an invalid clause composition.
- A query inside `COUNT` or `COLLECT` cannot update the graph, and `COUNT` and `COLLECT` followed by parentheses stay the aggregates.
- `VALUE { query }` takes the bodies of `COLLECT` under the same scope rules, and gives the value of the one column in the one row its query returns, or null when the query returns no row.
- A `VALUE` query that returns more than one row fails with `ErrorKind::CardinalityViolation`, which depends on data and never on the query text alone.
- A query inside `VALUE` cannot update the graph, and `VALUE` is a keyword only before `{`, so it still works as a name.
- `reduce(accumulator = init, variable IN list | body)` folds the list from the left, gives `init` for an empty list and null for a null list, and its body cannot aggregate.
- `[OPTIONAL] CALL { query }` runs its query once per incoming row and extends the row with each row the query returns, and `OPTIONAL CALL` keeps a row whose query returns none, with nulls.
- A `CALL` query sees the outer variables its scope clause names, `(a, b)`, `()`, or `(*)`, and without a scope clause those that the plain variable items of a leading `WITH` name, so any other name inside is a new variable.
- A `CALL` query cannot return a column named like an outer variable.
- A `CALL` query may update the graph, and then it may end without `RETURN`, which keeps each incoming row once whatever the query gives.
- A `CALL` query that does not update the graph must end with `RETURN`.
- A `CALL` query runs to its end for one incoming row before it runs for the next, so each run sees the writes of the runs before it.
- A `CALL` whose query updates the graph is an updating clause, so a reading clause after it needs a `WITH` between them.
- A query inside `EXISTS`, `COUNT`, or `COLLECT` cannot update the graph, even through a `CALL` inside it.
- An element that a `CALL` query deletes is returned after the `CALL` as it was when deleted, under the rules for elements deleted earlier in the same query.
- A `CALL` query may join single queries with `UNION` or `UNION ALL`, under the column rule of a top-level `UNION`.
- A simple `CASE` branch takes a list of tests of the scrutinee, each a value it must equal, a comparison operator and a value, or `IS [NOT] NULL`, and the scrutinee is evaluated once.
- `ORDER BY` takes `NULLS FIRST` and `NULLS LAST`, and without them nulls sort last ascending and first descending.
- GQL's function names `upper`, `lower`, `char_length`, `character_length`, `byte_length`, `octet_length`, `cardinality`, `path_length`, `ln`, `power`, `mod`, `sinh`, `cosh`, `tanh`, `cot`, `nullif`, and two-argument `log(base, value)` exist next to the Cypher names.
- `randomUUID()` gives a new random version 4 UUID in its hyphenated lowercase form at each call.
- `haversin(x)` is `(1 - cos(x)) / 2`.
- `round(value, precision [, mode])` rounds the shortest decimal form of the value to `precision` places, with the modes `UP`, `DOWN`, `CEILING`, `FLOOR`, `HALF_UP` by default, `HALF_DOWN`, and `HALF_EVEN`, and a negative precision fails as a number out of range.
- `timestamp()` gives the statement clock in milliseconds since the Unix epoch.
- `ceiling` is another name for `ceil`.
- `toBooleanList`, `toIntegerList`, `toFloatList`, and `toStringList` convert each item of a list as the `OrNull` conversions do.
- `vector.similarity.cosine` and `vector.similarity.euclidean` follow Neo4j: `(1 + cosine) / 2` and `1 / (1 + d²)`, null when an item is null or a cosine vector is zero, and an error for vectors of different lengths.
- `CURRENT_DATE`, `CURRENT_TIME`, `CURRENT_TIMESTAMP`, `LOCAL_TIME`, `LOCAL_TIMESTAMP`, and `LOCAL_DATETIME` without parentheses read the statement clock, unless a variable of that name is in scope.
- `trim([LEADING | TRAILING | BOTH] [characters] FROM text)` and two-argument `ltrim`, `rtrim`, and `btrim` strip any character of `characters` rather than one character string.
- Cypher's `isEmpty`, `isNaN`, `elementId`, and the `OrNull` conversions exist, and `elementId` gives a string that names the kind and ID of the element.
- Single queries join with GQL's `EXCEPT`, `INTERSECT`, and `OTHERWISE` as well as `UNION`, from left to right, and one query uses only one operator.
- `EXCEPT` and `INTERSECT` compare rows as `DISTINCT` does, give distinct rows by default, and treat the rows as multisets with `ALL`.
- `OTHERWISE` gives the rows of its left operand, or of its right operand when the left gives none.
- GQL's `||` joins two strings or two lists, binds like `+`, and is a type error on anything else, while `+` keeps Cypher's wider rules.
- `||` is an operator only when its two pipes touch, so a lone `|` still ends a comprehension filter or a label disjunction.
- `NEXT` passes the rows a statement returns to the statement after it, whose only variables are the columns of those rows.
- `NEXT YIELD a, b` keeps only the named columns of the rows it passes on.
- Each statement after `NEXT` runs once over all the rows the statement before it returned, so an aggregate or a set operator there sees all of them.
- A statement that ends without `RETURN` passes on one row without columns, and one that does not update the graph must end with `RETURN`.
- A statement after `NEXT` starts the clause order rules afresh, so it may read after the statement before it updated the graph.
- `NEXT` joins statements more loosely than any set operator, and works inside `CALL { ... }`.
- `NEXT` is a keyword only between two statements, so it still works as a variable, label, or relationship type.
- A chain of statements joined by `NEXT` counts as one extra level of nesting toward the parser's limit.
- A `CALL` that is the only clause inside `EXISTS` follows the rules of a `CALL` inside a larger query.
- A `CALL` inside a larger query passes the arguments of a procedure that takes any.
- A `CALL` inside a larger query binds only its `YIELD` items.
- A `CALL` inside a larger query rejects `YIELD *`.
- A `CALL` gives one row per row the procedure returns.
- A `CALL` of a procedure without outputs keeps each row once.
- Patterns accept every GQL edge form, full and abbreviated: `<-`, `->`, `-`, `<->`, `~`, `<~`, and `~>`.
- Every stored relationship is directed, so `~` matches no relationship, and `<~` and `~>` match what `<-` and `->` match.
- A variable-length `~` edge still matches a path of zero hops.
- `<~>` and `<~[]~>` are syntax errors.
- A pattern that creates rejects the edge forms with `~` as missing a direction, and `INSERT` also rejects `-` and `<->`.
- A label test on a relationship treats its type as its only label, so `r:T` is true when the type is `T`.
- Label expressions take `|`, `&`, `!`, `%`, and parentheses, with `|` binding weakest and `!` tightest.
- `!` applies to a label, `%`, or a parenthesized expression, so `!!A` is a syntax error.
- `%` is true of an element with at least one label, so it is true of every relationship.
- A node or relationship pattern introduces its label expression with `:` or `IS`.
- `IS` starts a label expression in a pattern only when a label expression follows it, so a variable can still be named `is`.
- Cypher's `:A:B` is the conjunction of `A` and `B`, and it only joins plain label names, so mixing it with another label operator is a syntax error.
- A relationship pattern takes a single `:`, so `[:T:U]` is a syntax error.
- A `:` may follow a `|`, as in Cypher's `[:T|:U]`.
- A label test in an expression takes a label expression after `:` or after `IS LABELED`, and `IS NOT LABELED` is its negation.
- `IS LABELED` and `IS NOT LABELED` bind like `IS NULL`.
- Inside the `WHERE` of a list or pattern comprehension, a `|` that no parenthesis, bracket, brace, or `CASE` within the filter encloses starts the projection, so only a label disjunction at the top of the filter needs parentheses.
- A node in a pattern that creates takes only a label or a conjunction of labels, and anything else fails with its own error kind.
- `SET` and `REMOVE` take labels after `:` or `IS` in the same forms, so `n:A:B`, `n:A&B`, and `n IS A&B` name the same labels, and a label expression with `|`, `!`, or `%` fails with the same error kind.
- A `DELETE` target that is a label test, alone or under `NOT`, `AND`, `OR`, or `XOR`, fails as an invalid delete rather than as an argument of the wrong type.
- Inside an expression, a single `-` between parenthesized terms is always subtraction.
- A malformed number literal is an invalid number where a value is expected, and an unexpected token anywhere else.
- Parameters are data and never take part in the type checks made on the query text.
- A database binds each query text once and reuses the plan for later runs with other parameter values.
- Registering a procedure forgets every bound plan.
- An element deleted earlier in the same query is returned as it was when deleted.
- Reading the properties of an element deleted earlier in the same query fails.
- The type of a relationship deleted earlier in the same query stays readable, through `type()` and label tests.
- Reading the labels of a node deleted earlier in the same query fails.
- A `MERGE` property that evaluates to null is an error.
- `range()` has a length cap, so one query cannot exhaust the host's memory.
- Floats convert to strings in the same form as the openCypher reference implementation.
- Each function declares the argument types it accepts once, and both the check on the query text and the check on data read that declaration.
- `length()` takes a path, and `size()` takes a list or a string.
- An argument of `range()` that is not an integer fails with its own error kind, under the same early type-error rule.
- Every other function argument of the wrong type, including a non-integer one where only an integer fits, fails as an ordinary argument type error.
- `sum`, `avg`, `stDev`, `stDevP`, and the percentile aggregates take numbers only.
- An aggregate argument cannot call `rand()`.
- A percentile aggregate over a group with no rows is null and does not evaluate its percentile.
- A null percentile makes a percentile aggregate null.
- Operators, indexing, slicing, and label tests fall under the early type-error rule for every operand whose type the query text fixes, including node, relationship, and path variables.
- The type the query text fixes leaves out null, so an operand that may be null, such as a comparison or an `OPTIONAL MATCH` variable, still fails early when no value of its type fits.
- Aggregate arguments, pattern properties and filters, pattern predicates, and pattern comprehensions fall under the early type-error rule.
- A reading clause that follows an updating clause needs a `WITH` between them.
- `FILTER` keeps the rows whose condition is true, with or without `WHERE` after the keyword, and keeps every variable in scope.
- A `FILTER` condition is a `WHERE` in every rule above, so it may hold a pattern predicate and may not aggregate.
- `FILTER` is a reading clause, so it cannot end a query and does not separate an updating clause from a reading clause after it.
- `LET` binds each value to a new variable and keeps every variable in scope.
- A `LET` variable cannot already be in scope, so `LET` never shadows or rebinds a variable.
- The values of one `LET` see only the incoming row, not the variables the same `LET` binds.
- A `LET` value cannot aggregate.
- `LET` is a reading clause under the same clause-order rules as `FILTER`.
- `LET` accepts only `variable = value`, without the `VALUE` keyword or a declared type.
- A `WITH` item without an alias is reported only after the projection's expressions, including its `ORDER BY`, bind without error.
- A column projected twice is reported after a `WITH` item without an alias.
- `split()` by the empty string gives one string per character, so it gives an empty list for the empty string.
- `toInteger()` and `toFloat()` read text only in the decimal number literal syntax with an optional sign and optional surrounding whitespace, and give null for anything else.
- Temporal values follow openCypher: `date`, `localtime`, `time`, `localdatetime`, `datetime`, and `duration` build them from a map, a string, or another temporal value.
- The temporal functions `truncate`, `transaction`, `statement`, `realtime`, `fromepoch`, `fromepochmillis`, `between`, `inMonths`, `inDays`, and `inSeconds` exist under the openCypher names.
- A temporal value built without a time zone gets UTC.
- The `statement` clock and the clock of a call without arguments read one instant per query, so two calls in one query agree.
- The `transaction` clock reads one instant per transaction, as decided in the transactions doc.
- The `realtime` clock reads the system clock at each call.
- Temporal values convert to strings in the ISO 8601 forms the TCK expects.
- A temporal function reads back every string it produces.
- A fractional duration component carries into the next smaller units, with a month of 30.436875 days.
- The carry is exact and only the nanoseconds are truncated, except where one of the limits below first truncates an amount toward zero.
- A duration string amount keeps its whole part exactly and drops only fraction digits worth less than a nanosecond in any unit.
- A float that multiplies or divides a duration counts as the shortest decimal that reads back as it.
- A duration multiplied by a number keeps a fixed number of decimal places of each unit, set in code.
- A duration divided by a number too large for an exact fraction keeps the same fixed number of decimal places of each unit.
- A duration divided by a number so large that the quotient is far below a nanosecond is the zero duration.
- Any other product or quotient that fits in the duration range is computed exactly.
- A duration divided by an infinite float is the zero duration.
- A duration divided by NaN, or multiplied by an infinite float or NaN, raises an invalid temporal value error, even when the duration is zero.
- Adding a duration to a temporal value adds months, then days, then seconds and nanoseconds, and drops the units the value does not have.
- A date moves by the whole days in the seconds and nanoseconds of a duration, truncated toward zero.
- `<`, `<=`, `>`, and `>=` compare two temporal values of the same type and give null otherwise.
- Times and datetimes compare by instant alone, so the same instant at two offsets or zones is neither less nor greater, even though the two are not equal.
- Durations do not compare.
- Two times or two datetimes are equal when they have the same instant and the same offset or zone.
- Two durations are equal when their months, days, seconds, and nanoseconds are.
- `ORDER BY` places temporal values after paths and before strings.
- `ORDER BY` sorts temporal types in the order datetime, local datetime, date, time, local time, duration.
- Within a temporal type, `ORDER BY` sorts by instant or by value, and then by offset and zone.
- A temporal argument that does not parse, a map key a temporal function does not know or cannot combine, and a component outside its range fail with their own error kind.
- That error kind depends on values and never on the query text alone.
- `IS TYPED type` and Cypher's `IS :: type` test whether a value belongs to a type, and never give null.
- A type is a name from GQL or Cypher, such as `INTEGER`, `INT`, `STRING`, `ZONED DATETIME`, or `TIMESTAMP WITH TIME ZONE`, `LIST<type>` or `type LIST`, `ANY`, `NOTHING`, or `NULL`, optionally followed by `NOT NULL`.
- A type may be a union joined by `|` or written `ANY<...>`, and a union at the top of a comprehension filter needs parentheses, as a label disjunction does.
- Null belongs to every type not declared `NOT NULL` except `NOTHING`, and a list belongs to `LIST<type>` when every item belongs to `type`.
- `valueType(value)` gives the name of the most specific type of a value, in Cypher's form such as `INTEGER NOT NULL` or `LIST<INTEGER | STRING> NOT NULL`.
- `valueType` lists the item types of a list in a fixed order set in code, marks them `NOT NULL` when the list holds no null, and gives `LIST<NOTHING>` for an empty list.
- `CAST(value AS type)` keeps null and a value of the target type, and converts numbers, booleans, and temporal values to text, text to numbers, booleans, and temporal values, integers to floats, floats to integers toward zero, temporal values to other temporal types, and lists item by item.
- `CAST` of any other value, or of text that does not read as the target type, fails with `ErrorKind::InvalidCast`, except that malformed temporal text fails as an invalid temporal value.
- `CAST` reads text as the conversion function of the target type does, such as `toInteger` for `INTEGER` and `date` for `DATE`.
- `IS TRUE`, `IS FALSE`, and `IS UNKNOWN` test a boolean, where null is unknown, never give null, and fail on any other type.
- `IS DISTINCT FROM` compares two values as `DISTINCT` does, so two nulls are not distinct, and it never gives null.
- `normalize(text [, form])` and `text IS [form] NORMALIZED` take the form `NFC`, `NFD`, `NFKC`, or `NFKD`, as a bare word or a string, with `NFC` by default.
- `NFC`, `NFD`, `NFKC`, and `NFKD` are read as forms only as the last argument of `normalize`, so they still work as names elsewhere.
- A path pattern takes GQL's path search prefix: a selector `ANY SHORTEST`, `ALL SHORTEST`, `ANY [k]`, `SHORTEST k`, `SHORTEST [k] GROUP[S]`, or `ALL`, a path mode `WALK`, `TRAIL`, `SIMPLE`, or `ACYCLIC`, or both, each optionally followed by `PATH` or `PATHS`.
- The count of a selector is an integer literal.
- A selector chooses, among the matches of its path pattern with the same start and end node, the shortest paths it asks for, and `ANY k` takes the `k` shortest.
- A selector chooses before the `WHERE` of its `MATCH` filters.
- With a selector or a mode and no mode named, the path mode is `WALK`.
- A pattern part with a quantified path pattern and no prefix keeps Cypher's rule that no two relationships of a `MATCH` are the same, and is otherwise a `TRAIL`.
- The relationships of a pattern part with a prefix take no part in that rule.
- An unbounded quantifier in a `WALK` without a selector is a syntax error of kind `ErrorKind::InvalidPathPattern`.
- A quantified path pattern `(element [WHERE condition]){m,n}` takes `{m}`, `{m,}`, `{,n}`, `*`, and `+`, and so does an edge pattern, as in `-[:T]->+`.
- A quantified edge means the same as Cypher's variable-length relationship with those bounds.
- A quantified path pattern holds at least one edge, no variable-length relationship, and no other quantified path pattern.
- The first node of a quantified path pattern joins the node before it, and its last node the node after it, which is anonymous where the query writes none.
- A variable of a quantified path pattern is a singleton inside its `WHERE` and a list of its iterations' elements after it, and cannot be bound before it.
- The property maps of a pattern part with a prefix or a quantified path pattern read no variable of that part but its start node, and a `WHERE` inside a quantified path pattern also the elements of its own iteration.
- A selective path pattern shares only its start and end nodes with the other pattern parts of its `MATCH`.
- A parenthesized path pattern without a quantifier, and a nested quantified path pattern, fail as unsupported.
- Cypher's `shortestPath(pattern)` is `ANY SHORTEST` and `allShortestPaths(pattern)` is `ALL SHORTEST`, over one relationship pattern whose minimum length is 0 or 1, as a `TRAIL`.
- The conjuncts of the `WHERE` of a `MATCH` that read the inside of a Cypher shortest path pattern hold on each path before the shortest are chosen, as in Neo4j.
- `=~` is true when the regular expression on its right matches the whole string on its left.
- Regular expressions follow the syntax of the Rust `regex` crate, so lookaround and backreferences are not accepted.
- Matching takes time linear in the length of the string, whatever the pattern.
- `=~` gives null when either operand is null or not a string, like `STARTS WITH`, so it raises no type error.
- A pattern is compiled only when both operands are strings.
- A pattern that is not a valid regular expression fails with its own error kind.
- A pattern whose compiled form passes a size limit set in code fails with the same error kind.
- That error kind depends on values and never on the query text alone.

## Open

- Whether a variable, alias, or `YIELD` name that is a reserved word fails where it is bound, as in Cypher, rather than where the query reads it back.
- What `TRUE`, `FALSE`, `NULL`, `DISTINCT`, and `NOT` mean when bound as a variable, since reading one back now gives the literal, the modifier, or the operator instead of the variable.
